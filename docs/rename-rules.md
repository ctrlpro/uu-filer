# 重命名规则

从规则库添加步骤，在应用区叠加、排序、启停；选中步骤后编辑参数。文件列表显示最终结果，参数区显示当前文件在此步的输入、输出及提取字段。

## 常用操作

| 规则             | 参数与行为                                                                           |
| ---------------- | ------------------------------------------------------------------------------------ |
| 高级查找替换     | 文字或正则、区分大小写、全部匹配或第 N 次、名称/扩展名/完整文件名范围                |
| 插入删除与截取   | 按位置、文字前后定位；偏移从 0 开始；按可见字符计数，不拆开组合字符或 emoji          |
| 自定义清理       | 自定义字符、保留字符、括号内容、副本标记、括号数字、重复分隔符、不可见字符；独立选择 |
| 字符宽度与规范化 | 全角 ASCII 与半角转换、NFC；不自动把圈号等其他字符折叠成数字                         |
| 正则提取字段     | 编号或命名捕获组；未匹配可标记问题；新提取替换之前的捕获字段                         |
| 按分隔符提取字段 | 从 1 开始，生成 `{1}`、`{2}` 等字段                                                  |
| 模板重组         | 文字、原名/当前名、本地变量和提取字段组合；缺失必需字段时阻止操作                    |
| 条件与分支       | 单个条件、全部满足、任一满足、取反；分别编辑满足与否则分支                           |
| 批量文字映射     | 多组原文字 → 新文字；精确或局部匹配；局部匹配按表中顺序优先，一次处理，不级联        |
| 分组与步长编号   | 起始值、步长、补零、前后置或仅编号；全局、按目录、按提取字段分组                     |
| 已有数字调整     | 第 N 组或全部数字增减、补零；超出范围时标记问题                                      |
| 日期识别与转换   | 明确输入格式、输出格式；名称日期、提取字段、修改时间或当天日期；可写回字段           |
| 修改扩展名       | 大小写、设置或移除；仅改名称，不转换文件格式                                         |

基础查找替换仍按字面处理。旧方案继续使用原有规则语义，包括旧版“清理副本”删除末尾括号数字的行为；新添加的清理规则不会默认删除括号数字。

## 完整替换原名称

完整替换默认只替换名称主体，保留原扩展名。例如 `xxxx.jpg → 0001.jpg`。

- **连续编号**：编号位置选择“完整替换名称”，位数选 4，得到 `0001.jpg`、`0002.jpg`。
- **分组与步长编号**：编号位置选择“完整替换名称（仅编号）”，仍可按目录/字段分组编号。
- **添加日期**：日期位置选择“完整替换名称”，得到 `2026-01-05.jpg`。
- **日期识别与转换**：输出方式选择“完整替换名称（仅日期）”，可以使用原名中的日期、提取字段、修改时间或设备日期。
- **直接设置名称**：填写名称主体，例如“照片”，得到 `照片.jpg`；按普通文字处理，不解析模板变量。
- **模板重组、整名映射**：原本就支持完整替换；模板只需省略 `{name}` / `{original}`，映射选择整个名称匹配。

完整替换会覆盖之前步骤得到的名称主体，后续步骤继续叠加。例如“直接设置名称：照片 → 连续编号后置”得到 `照片_0001.jpg`。同类扩展名的文件若被设置为同名，会显示冲突并阻止执行；可追加编号解决。复合扩展名是否整体保留由方案选项决定。

## 字段与模板

| 变量                             | 含义                                             |
| -------------------------------- | ------------------------------------------------ |
| `{original}`                     | 原始名称，不含扩展名                             |
| `{name}`                         | 经过之前步骤处理的当前名称，不含扩展名           |
| `{parent}`                       | 父目录名，在本地代入，不是完整路径               |
| `{size}`                         | 文件大小，字节                                   |
| `{modified:YYYY-MM-DD_HH-mm-ss}` | 修改时间；使用该时间点的设备时区偏移             |
| `{today:YYYYMMDD}`               | 预览中固定的设备日期基准；在方案选项中可更新     |
| `{客户}`、`{日期}`、`{1}`        | 正则或拆分步骤提取的字段                         |
| `{field:name}`                   | 明确读取名为 name 的提取字段，避免与内置变量重名 |

扩展名默认另行保留，不在模板中填写 `{ext}`。需要修改时添加扩展名规则。缺失或空的字段会成为问题项，不会自动补成“未知”等文字。

“方案选项”控制排序、升降序和扩展名识别。自然排序使 `2` 排在 `10` 前。新方案默认将 `.tar.gz`、`.tar.bz2`、`.tar.xz`、`.tar.zst`、`.tar.lz`、`.tar.lzma`、`.user.js`、`.d.ts` 作为复合扩展名处理；其他情况按末段扩展名处理。隐藏文件 `.env` 和无扩展名的 `README` 不会被误拆分。需要其他行为可选择末段扩展名模式。

排序和日期基准进入预览，真正执行时使用固定的新名称，不重新编号、不重新询问模型。搜索和状态筛选只改变显示；修改选择范围会重新计算编号。

## 示例：合同字段重排

把 `华星-20260105-HT003.pdf` 改为 `2026-01-05_华星_HT003.pdf`：

1. 添加“正则提取字段”：`^(?P<客户>.+)-(?P<日期>[0-9]{8})-(?P<编号>.+)$`。
2. 添加“日期识别与转换”：来源选提取字段 `日期`，输入 `YYYYMMDD`，输出 `YYYY-MM-DD`，输出方式选择写回字段。
3. 添加“模板重组”：`{日期}_{客户}_{编号}`。

如果列表有多种结构，用“条件与分支”分别提取，再接公共日期转换与模板。若要求缺号的保持原样，明确把条件设置为名称结构或字段存在后才处理。未匹配条件是正常保留；未匹配必需提取、缺失模板字段、非法日期和名称冲突则是问题。

## 示例：编号与已有数字

- 在方案选项中选择自然排序，添加“分组与步长编号”，起始 1、步长 1、补零 3，得到 `照片_001.jpg`。
- 编号分组选按目录，各目录独立计数，即使列表交错排列也不会相互串号。
- 先提取客户字段，编号分组选按提取字段 `客户`，每个客户独立计数。
- 使用“已有数字调整”，增减 1、补零 3、处理第 1 组，`第9集.mp4` → `第010集.mp4`。

## 示例：避免重复添加前缀

添加“条件与分支”，字段选 `name`，比较方式选开头是，比较值 `项目_`，勾选不满足时应用。在满足分支中放“添加前缀”，文字为 `项目_`。这样重复使用时不会继续添加前缀。

## AI 方案

默认的自然语言任务只参考获准文件名。可以要求模型自行设计提取模式与模板，例如：

> 根据列表中的不同文件名格式，提取客户、日期、合同号，以“日期_客户_合同号”重组。日期统一 YYYY-MM-DD，缺合同号的保持原样，不读正文。

语义整理或翻译可以输出逐文件名称建议。此类建议绑定原文件 ID，只对本批有效，先于普通规则运行，不保存成通用方案。

在“目标示例与当前方案”中，可以提供最多 8 个期望结果；勾选参考当前规则后，也可以要求调整现有方案。需要改变排序时，AI 可同时提出方案选项，草案中可审查。例如“按修改时间升序编号”，会生成排序选项和编号规则。

草案先在全部已选操作对象上本地试算。可以编辑草案参数，筛选和分页检查结果；问题项或不满足示例时不能采用。追加保留当前规则，替换需要额外确认。采用方案仍然只更新预览，文件操作需单独确认。

参考超过 200 个获准名称时，先检查权限，再按扩展名与命名结构取代表样本，期望结果示例优先纳入。发送预览显示实际发送的名字、当前规则和目标示例。未发送的名字不声称已由模型理解，但会参与最终本地规则试算。正文理解默认关闭，逐文件内容任务每次最多 20 个文件。

条件或字段校验只能保证指定约束与名称规则成立，不代表语义一定正确。模型质量仍取决于用户选用的模型；普通开发测试使用协议夹具，不下载或运行真实模型。本地 Ollama 请求使用 16K 上下文设置，实际支持情况与内存需求取决于模型。

## 语法和限制

- 正则采用 Rust `regex` 语法，支持 Unicode 和命名捕获组 `(?P<字段>...)`；不支持环视和模式内反向引用。替换引用使用 `${1}` 或 `${字段}`。字面的 `$` 可使用普通文字模式。
- 日期输入必须明确年月日顺序，标记为 `YYYY`、`MM/M`、`DD/D`、`HH`、`mm`、`ss`。例如 `YYYY年M月D日`。不自动猜测日期顺序，不允许非法日期、两位年份或多个日期混淆。
- 全局最多 64 个步骤，总计含分支最多 128 条；AI 草案含分支最多 32 条。每个分支最多 16 条，分支/条件最多嵌套 4 层，条件组最多 8 项。
- 映射表最多 256 项，编号补零最多 12 位，单步输入输出最多 4096 字节。正则编译和整批工作量均有限制，超出时停止试算，不执行文件操作。
- 最终名称继续使用现有跨平台校验：非法字符、保留名称、路径、超长名称和目标覆盖均不能直接执行。
- 桌面使用统一 Rust 引擎；浏览器仅演示基础规则，遇到高级表达式明确提示需要桌面应用。桌面 IPC 界面测试直接调用同一 Rust 引擎适配器。
- EXIF/音频标签、CSV、关联文件、拼音、哈希、随机串、目录本身改名尚未加入本版本。没有捆绑外部工具、脚本解释器或模型。
