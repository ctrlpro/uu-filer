# UU Filer

本地优先的文件批量管理桌面工具。Tauri 2 + Rust + React / TypeScript，面向 Windows 和 macOS。

## 当前版本

- 添加文件、文件夹与子目录；桌面拖放；搜索与类型筛选。
- 查找替换、前后缀、大小写、去空格、编号；本地保存命名方案。
- 可编辑的逐项预览、冲突检测、批量重命名、复制、移动。
- SQLite 操作记录；SHA-256 内容检查；互换名称；撤销和中断后的尽力恢复。
- 文件/目录级 AI 权限，默认仅本地，严格的父目录策略优先。
- Ollama 独立本地实例（禁用云端功能）及兼容 OpenAI 的 HTTPS 服务。
- AI 支持文件名、文本、文字型 PDF、JPG/PNG/WebP 图片；模型依据与发送预览。
- Windows / macOS 系统凭据库保存 API Key，不降级为明文保存。

Office 正文提取、扫描 PDF 的 OCR、音视频转写、自动分类、任务取消/断点续跑尚未实现。这些文件目前可以使用普通规则重命名。正则表达式和可拖动的规则流水线也留待后续版本。

## 开发

需要 Node.js 22+、npm、稳定版 Rust 和 [Tauri 平台开发依赖](https://v2.tauri.app/start/prerequisites/)。Windows 需要 Visual Studio C++ Build Tools 与 WebView2；macOS 需要 Xcode Command Line Tools。使用现有仓库，不需要创建 worktree。

```sh
npm ci
npm run desktop
```

仅预览界面：

```sh
npm run dev
```

浏览器模式清楚标记为演示，可加载示例文件并测试规则；不会修改磁盘，不会调用 AI。选择浏览器文件仅读取文件名、大小等属性，不读取正文。

检查与打包：

```sh
npm run build
npm test
npm run test:core
npx playwright install chromium
npm run test:e2e
npm run desktop:build
```

已有 Chromium 时，可设置 `CHROMIUM_PATH` 来运行界面测试。Windows/macOS 安装包需要在对应系统构建。GitHub Actions 配置包含双平台构建与未签名安装包工件；签名、公证和真实系统验收仍需单独完成。当前 Linux 云机器的通过结果不代表 Windows/macOS 真机测试已通过。

本云环境可运行 `bash scripts/setup-cloud.sh` 准备依赖，再 `source scripts/cloud-env.sh`。Linux 的只读系统目录下不安装软件，GTK/WebKit 开发包从 Debian 签名仓库下载并解压到 `/workspace/.tools/sysroot`。该脚本仅针对 Debian 13 云环境。

## 使用本地 AI

1. 安装 [Ollama](https://ollama.com)，下载适合硬件的文本模型；理解图片还需要视觉模型。
2. 打开「AI 智能命名」，选择本地 Ollama，点击「检测」。
3. 应用启动单独的回环地址实例，设置 `OLLAMA_NO_CLOUD=1`，共享已下载的模型，不向现有 Ollama 实例发送文件。
4. 选择文件并输入要求，查看本地待处理内容，生成建议并核对。

不会自动下载模型，不会在本地请求失败后切换云端。模型不存在、能力不匹配或独立实例启动失败时会给出错误。退出时应用持有的 Ollama 进程会被终止；强制杀死应用进程可能需要手动结束其子进程。

## 使用云端 AI

在设置中填写 HTTPS 服务基础地址（通常以 `/v1` 结束）、模型与 API Key。Key 按完整服务地址分别保存在系统凭据库中。先明确将文件设为「允许云端」，再生成发送预览；点击同意后才发起请求。对话预览包括系统要求、文件名、提取的文字及实际发送的图片，不携带完整源路径。

每次授权仅能使用一次，5 分钟后失效，绑定服务器内存中的具体请求与服务。文件属性或隐私策略改变会取消旧任务。请求禁止 HTTP 重定向，避免凭据被转发至其他地址。

AI 每批最多 20 个文件。文本最多读取前 32 KB；PDF 最大 20 MB、提取后截取前 16,000 个字符（不是摘要）；扫描 PDF 会跳过。图片最大 20 MB，在本地缩小到最长边 1024 像素后重新编码为 JPEG，不附带原始 EXIF；图片中的可见敏感信息仍会保留，发送前需要用户检查。

兼容服务需要支持 Chat Completions；应用请求 JSON 输出，图片需要视觉模型。有些服务并不完整实现兼容接口，实际可用性取决于服务与模型。

## 文件与隐私边界

- 「禁止 AI」连文件名也不会发送给模型；仍允许用户发起的普通文件操作和校验。
- 无显式策略时默认仅本地；显式文件和祖先目录规则中采用最严格的策略。
- 目录规则使用实际路径；扫描不跟随符号链接。重命名/移动/复制时保留原有隐私限制。
- AI 只返回名称和依据。路径、未知文件 ID、重复 ID、扩展名改变会被拒绝，模型不执行命令或文件操作。
- 默认不将提取正文、图片或模型对话写入数据库。待确认内容暂存在内存中，取消、发送后移除；过期任务在下一次准备任务时清理，退出时释放。
- SQLite 保存操作路径、内容哈希、设置与权限；系统本身的用户权限和磁盘加密负责保护这些本地元数据。
- 自动敏感信息识别尚未实现；文件/目录权限与发送预览是当前保护机制。

## 操作安全与限制

所有操作先预览并再次检查源文件；已有目标绝不主动覆盖。重命名先将整批源文件安全暂存，再逐个完成目标名称，支持名称互换和大小写变化。暂存使用同文件系统的硬链接与删除，因此文件系统需要支持硬链接；不支持时停止并保留源文件。复制/移动使用独占创建目标并校验 SHA-256，移动在校验通过后删除源文件。

日志不是跨文件系统事务：断电、权限变化、磁盘写满、外部程序同时操作都可能造成部分完成。失败后停止，在「操作记录」中尝试恢复；遇到内容变化、现有原文件或无法验证的部分输出会拒绝自动恢复，需用户检查。不要手动删除 `.uu-filer-*` 暂存文件。首次使用请先选择副本测试，重要文件仍应有独立备份。

当前不保证保留复制文件的全部 ACL、扩展属性、资源叉和时间戳；不适合直接搬迁依赖这些属性的应用包或系统目录。大文件校验和内容提取期间尚不支持中途取消。
